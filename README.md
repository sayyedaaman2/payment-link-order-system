# Payment Link Order System

A robust Node.js and MongoDB backend for managing orders and automating payment workflows using Razorpay Payment Links. This system features secure webhook integration to track payment statuses in real-time.

- **Live Demo**: [https://payment-link-order-system.onrender.com](https://payment-link-order-system.onrender.com)
- **API Documentation**: [https://payment-link-order-system.onrender.com/api-docs](https://payment-link-order-system.onrender.com/api-docs)

## 🚀 Project Overview

This project provides a complete workflow for:
- Creating orders and generating Razorpay Payment Links.
- Managing order lifecycle (Pending -> Paid/Failed).
- Securely handling payment confirmation via Razorpay Webhooks.
- RESTful API for order management.

## 🏗 Architecture Flow

1. **Order Creation**: The client sends a request to create an order. The server creates a record in MongoDB and generates a Razorpay Payment Link.
2. **Payment Link**: The short URL generated by Razorpay is returned to the client.
3. **User Action**: The user completes the payment on the Razorpay-hosted page.
4. **Webhook Notification**: Razorpay sends a POST request (`payment.captured`) to our webhook endpoint.
5. **Signature Verification**: The server verifies the `x-razorpay-signature` using the `RAZORPAY_WEBHOOK_SECRET`.
6. **Order Update**: Upon successful verification, the order status is updated to `paid` in the database.

## 🛠 Tech Stack

- **Runtime**: Node.js (ES Modules)
- **Framework**: Express.js
- **Database**: MongoDB (Mongoose ODM)
- **Payment Gateway**: Razorpay
- **Logging**: Pino & Pino-pretty
- **Security**: HMAC SHA256 Webhook Verification, CORS, Rate Limiting
- **Documentation**: Swagger UI & Postman

## 📋 API Endpoints

### Orders
| Method | Endpoint | Description |
|--------|----------|-------------|
| POST | `/api/v1/order` | Create order & generate payment link |
| GET | `/api/v1/order` | Fetch all orders |
| GET | `/api/v1/order/:id` | Fetch order by ID |
| PUT | `/api/v1/order/:id` | Update order details |
| DELETE | `/api/v1/order/:id` | Delete an order |

### Webhooks
| Method | Endpoint | Description |
|--------|----------|-------------|
| POST | `/api/v1/webhook/razorpay` | Razorpay webhook listener |

## 🗄 MongoDB Models

### Order Schema
```javascript
{
  customerName: String,
  product: String,
  amount: Number,
  currency: String, // Default: INR
  status: String, // pending, paid, failed
  paymentLink: String,
  razorpayPaymentId: String,
  razorpayOrderId: String, // Stores Razorpay Payment Link ID
  paidAt: Date
}
```

## ⚙️ Setup Instructions

1. **Clone the repository**
   ```bash
   git clone https://github.com/sayyedaaman2/payment-link-order-system.git
   cd payment-link-order-system
   ```

2. **Install dependencies**
   ```bash
   npm install
   ```

3. **Configure Environment Variables**
   Create a `.env` file in the root directory:
   ```env
   PORT=3000
   MONGODB_URI=your_mongodb_connection_string
   RAZORPAY_KEY_ID=your_razorpay_key_id
   RAZORPAY_SECRET=your_razorpay_secret
   RAZORPAY_WEBHOOK_SECRET=your_webhook_secret
   ```

4. **Start the server**
   ```bash
   # Development mode
   npm run dev

   # Production mode
   npm start
   ```

## ⚓ Webhook Explanation

The webhook controller ensures data integrity by:
1. **Raw Body Parsing**: Using `express.raw()` to get the unmodified request body for signature calculation.
2. **HMAC Verification**: Computing a signature using your `RAZORPAY_WEBHOOK_SECRET` and comparing it with the `x-razorpay-signature` header.
3. **Idempotency**: Checking if an order is already marked as `paid` before processing to prevent duplicate updates.
4. **Event Handling**: Specifically listening for `payment.captured` to trigger the fulfillment logic.
